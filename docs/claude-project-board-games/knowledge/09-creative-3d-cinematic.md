# الإبداع، والأبعاد الثلاثة، والمؤثرات السينمائية والصوتية — إصدار النخبة (أكتوبر ٢٠٢٦)

هدف كل لعبة: **لحظة يتذكّرها الطلاب**. هذه اللحظة تكشف المفهوم العلمي ولا تشتّت عنه، وتبقى ممكنة لأيدي أطفال على سبورة في صف مضاء.

هذا الإصدار يرفع السقف التقني: محرّك **WebGPU** مع لغة التظليل **TSL**، وجسيمات تُحسب على معالج الرسوم، ومجسّمات **Gaussian Splatting** مصوّرة من الواقع، وأصول مولّدة بالذكاء الاصطناعي ومضغوطة. لكن القاعدة الأولى لا تتغير: **كل لعبة تعمل كاملة على أضعف جهاز**، والتقنية العليا طبقة إضافية فوقها.

> **قاعدة التحقق:** واجهات three.js تتغير كل شهر. قبل كتابة أي كود ثلاثي الأبعاد:
> 1. اقرأ نسخة `three` في `package.json` بالمستودع.
> 2. ابحث في الويب عن ملاحظات إصدار تلك النسخة، وطابق الكود مع أمثلتها الرسمية (`node_modules/three/examples/`).
>
> الأكواد في هذا الملف **أنماط مرجعية**، لا نصوص تُنسخ بلا تحقق.

## ١. مولّد الأفكار (لا تكرار)
اختر عنصرًا من كل عمود، وتحقق ألّا تطابق لعبة موجودة في عنصرين من الثلاثة. الألعاب الموجودة في `src/data/board-games.ts` بالمستودع.

| العالم (القصة) | الآلية (بالبقاء أو الالتقاط والإفلات) | اللحظة المدهشة |
|---|---|---|
| غوص على اللؤلؤ في الخليج | صنّف في سلال | مجسّم ثلاثي الأبعاد يطير إلى مكانه في قوس |
| رحلة في الفضاء | ركّب على رسم أو مجسّم | المشهد يتحوّل: يومٌ يصير ليلًا، وبذرة تصير شجرة |
| مختبر عالِم صغير | رتّب تسلسلًا | آلاف الجسيمات تتجمّع فتتشكّل المفهوم نفسه (جسيمات GPU) |
| سوق تراثي أو مدينة حديثة | طابِق زوجين | الكاميرا تدور حول المجسّم لتكشف وجهًا خفيًّا |
| الصحراء والواحات | تعرّف على المضيء | ضوء يكشف ما تحت الماء أو داخل الجسم |
| داخل جسم الإنسان | ابنِ برجًا أو سلسلة بالعناصر الصحيحة | سلسلة تفاعلات: كل صواب يحرّك آلة كبيرة |
| آلة زمن | أنقِذ أو أطعِم: العنصر الصحيح يُنقذ شخصية | **الشيء الحقيقي يتجسّد:** مجسّم مصوَّر من الواقع (Splat) يظهر من الغبار |
| مملكة الحروف والأرقام | سباق فريقين، لكل فريق عالمه | مؤشّر يمتلئ ويُطلق حدثًا كبيرًا |

**طريقة العمل:**
1. اكتب ثلاث تركيبات مختلفة. لكل تركيبة سطر عن ناتج التعلّم الذي تخدمه اللحظة المدهشة.
2. استبعد ما يكرّر لعبة موجودة.
3. رشّح الأقوى تعلّمًا، لا الأجمل شكلًا فقط.
4. اذكر **طبقة الجودة** التي تحتاجها اللحظة المدهشة (القسم ٢)، وما يراه الطلاب على الطبقات الأدنى.

**أمثلة:**
- **«قاع الخليج»** (العلوم، الكائنات الحية): كائنات بحرية ثلاثية الأبعاد توضع في طبقات البحر. الماء يضيء عند الصواب، وفي الختام تظهر **محارة حقيقية مصوّرة** (Splat) تنفتح عن لؤلؤة.
- **«مصنع الكسور»** (الرياضيات): قطع بيتزا ثلاثية الأبعاد تُركّب في دوائر. الدائرة تكتمل وتدور ثم تخرج من الفرن.
- **«قطار الحروف»** (اللغة العربية): عربات تحمل الحروف وتُرتّب لتكوين كلمة. القطار ينطلق عبر نفق ويُنطق الصوت.
- **«غبار النجوم»** (العلوم، حالات المادة): عند كل صواب تتحوّل ٢٠ ألف جسيمة من حالة إلى أخرى أمام الطلاب: متراصّة (صلب)، ثم منزلقة (سائل)، ثم متطايرة (غاز).

## ٢. طبقات الجودة (إلزامي لكل لعبة ثلاثية الأبعاد)
اللعبة تكتشف قدرة الجهاز عند التشغيل وتختار طبقة. **الأهداف وأحجامها ومواضعها وقواعد اللعب واحدة في كل الطبقات**؛ الذي يتغيّر هو الزينة فقط.

| الطبقة | متى | ما يُسمح به |
|---|---|---|
| **A — النخبة** | WebGPU متاح (Safari 26+ على iOS/iPadOS، وكروم الحديث على أندرويد) والأداء ثابت | مواد TSL كاملة، وجسيمات GPU حتى ~٣٠ ألفًا، ومجسّم Splat واحد، ومعالجة لاحقة خفيفة |
| **B — القياسية** | WebGPU غير متاح، فيعمل `WebGPURenderer` تلقائيًا على WebGL2، أو هبط الأداء من A | الكود نفسه (TSL يُترجَم إلى GLSL)، وجسيمات ≤ ٢٠٠٠ بـ InstancedMesh، **بلا Splat** (يحلّ محلّه GLB أو صورة)، وبلا معالجة لاحقة |
| **C — الهادئة** | تقليل الحركة، أو جهاز ضعيف جدًا، أو فشل تهيئة 3D | بلا WebGL: SVG وCSS فقط، والمجسّمات صور ثابتة. **اللعبة قابلة للعب بالكامل** |

**الاكتشاف:**
```js
// /board-kit/… أو داخل js/scene3d.js للعبة — نمط مرجعي
import * as THREE from 'three/webgpu';

export async function createRenderer(canvas) {
  const reduce = matchMedia('(prefers-reduced-motion: reduce)').matches
    || document.documentElement.dataset.motion === 'reduce';
  const forced = new URLSearchParams(location.search).get('tier'); // للتجربة: ?tier=A|B|C
  if (reduce || forced === 'C') return { tier: 'C' };
  try {
    const renderer = new THREE.WebGPURenderer({
      canvas, alpha: true, antialias: true,
      forceWebGL: forced === 'B',              // لتجربة الطبقة B على جهاز يدعم WebGPU
    });
    await renderer.init();                       // إلزامي قبل أول إطار
    renderer.setPixelRatio(Math.min(devicePixelRatio, 1.5));
    renderer.setClearColor(0x000000, 0);         // شفاف فوق #board
    const tier = renderer.backend.isWebGPUBackend ? 'A' : 'B';
    return { renderer, tier };
  } catch (e) {
    console.warn('3D غير متاح، الطبقة C', e);
    return { tier: 'C' };
  }
}
```

**منظّم الجودة التلقائي:** قِس متوسط الزمن بين الإطارات في أول ثانيتين (أثناء الافتتاح، حين لا أهداف لليد). إن تجاوز ٤٥ م.ث فانزل طبقة: من A إلى B (قلّل الجسيمات، وأخفِ الـ Splat، ودقة البكسل 1)، ومن B إلى C. لا ترفع الطبقة أثناء اللعب، ولا تغيّر الطبقة إلا في لحظة بلا أهداف.

## ٣. الأبعاد الثلاثة بـ three.js داخل قيود الموقع

### الاستضافة المحلية (إلزامي)
سياسة أمان المحتوى (CSP) تسمح بالسكربتات من الموقع نفسه فقط. لا CDN ولا روابط خارجية.

- **مجلد المكتبة المشترك:** `public/board-kit/vendor/three/`، من حزمة npm `three` نفسها في المستودع (`node_modules/three/build/` و`examples/jsm/`). النسخة **r186 أو أحدث** (لازمة لـ Splat الأصلي).
  | الملف | الغرض |
  |---|---|
  | `three.core.min.js` | النواة المشتركة (يستوردها ما بعده) |
  | `three.webgpu.min.js` | محرّك WebGPU مع الرجوع التلقائي إلى WebGL2 |
  | `three.tsl.min.js` | دوال TSL |
  | `three.module.min.js` | للألعاب القديمة فقط (WebGLRenderer) |
  | `addons/…` | ما تحتاجه اللعبة من `examples/jsm/` **مع تبعياته**: مثل `loaders/GLTFLoader.js`، و`loaders/KTX2Loader.js`، و`libs/meshopt_decoder.module.js`، و`libs/basis/` |
  | `LICENSE` | رخصة MIT |
- إن لم تكن الملفات موجودة فاذكر في التسليم أنها تُضاف، ويضيفها Claude Code بنسخها من `node_modules`.
- **خريطة الاستيراد** في `index.html` قبل سكربت اللعبة. `three` و`three/webgpu` يشيران إلى الملف نفسه، كما في أمثلة three.js الرسمية:
  ```html
  <script type="importmap">{ "imports": {
    "three": "/board-kit/vendor/three/three.webgpu.min.js",
    "three/webgpu": "/board-kit/vendor/three/three.webgpu.min.js",
    "three/tsl": "/board-kit/vendor/three/three.tsl.min.js",
    "three/addons/": "/board-kit/vendor/three/addons/"
  } }</script>
  ```
- **ممنوع خلط نسختين في صفحة واحدة:** لا تستورد `three.module.min.js` في لعبة تستعمل `three/webgpu`. الأضواء والمواد من نسخة لا تعمل مع محرّك النسخة الأخرى، بلا رسالة خطأ.
- **CSP:** WebGPU لا يحتاج تعديلًا. لكن WebAssembly (فك ضغط KTX2 وDraco، وMediaPipe) يحتاج `'wasm-unsafe-eval'` في `script-src`، والعمّال (Workers) تحتاج `worker-src 'self' blob:`. تحقق من `next.config.ts` قبل الاعتماد عليهما.
- النماذج والأنسجة والأصوات في مجلد اللعبة: `public/<slug>/assets/`.

### ترتيب الطبقات
```
#board (SVG)  →  لوحة 3D شفافة  →  #hud (البطاقات والنصوص)  →  طبقة الجسيمات  →  #fx (مؤشرات الأيدي)
```
- لوحة 3D: `pointer-events: none`، وتُدرج قبل `#hud`.
- النص العربي يبقى في HTML، لا في المشهد ثلاثي الأبعاد.
- البطاقات فوق المجسّمات تكون شفافة حيث يظهر المجسّم، وإلا بدا باهتًا خلفها.

### محاذاة العالم على وحدات المسرح (حتى تصير المجسّمات أهدافًا لليد)
اجعل المستوى z = 0 يطابق المسرح تمامًا: نقطة العالم `(x, −y, 0)` تظهر عند `(x, y)` بوحدات u.
```js
import * as THREE from 'three/webgpu';

function alignCamera(cam, VW, VH) {          // VH = 1000 دائمًا
  const dist = VH / 2 / Math.tan(THREE.MathUtils.degToRad(cam.fov / 2));
  cam.aspect = VW / VH;
  cam.position.set(VW / 2, -VH / 2, dist);
  cam.lookAt(VW / 2, -VH / 2, 0);
  cam.updateProjectionMatrix();
  cam.updateMatrixWorld();
}
const toWorld = (x, y, z = 0) => new THREE.Vector3(x, -y, z); // z > 0 = أقرب إلى الكاميرا وأكبر
function toStage(cam, v, VW, VH) {
  const p = v.clone().project(cam);
  return { x: ((p.x + 1) / 2) * VW, y: ((1 - p.y) / 2) * VH };
}
// هدف يد يغطي المجسّم كما يظهر على المسرح:
function hitCircle(cam, obj, VW, VH, pad = 16) {
  const s = new THREE.Box3().setFromObject(obj).getBoundingSphere(new THREE.Sphere());
  const c = toStage(cam, s.center, VW, VH);
  const e = toStage(cam, s.center.clone().add(new THREE.Vector3(s.radius, 0, 0)), VW, VH);
  return { x: c.x, y: c.y, r: Math.hypot(e.x - c.x, e.y - c.y) + pad };
}
```
- استدعِ `alignCamera` في `render()` بعد حساب `VW`، ثم احسب أهداف المجسّمات في `_collectTargets()`.
- **في الطبقة C** لا توجد مجسّمات، فالأهداف تُحسب من عناصر HTML/SVG البديلة **في المواضع نفسها**.
- **حركات الكاميرا السينمائية** مسموحة فقط حين لا أهداف لليد (الافتتاح والختام: `targets()` تُرجع قائمة فارغة)، ثم تعود الكاميرا إلى المحاذاة.
- **العنصر المحمول:** يمكن أن يكون مجسّمًا يتبع اليد، يُنقل كل إطار إلى `toWorld(c.x, c.y, 90)`. تبقى `heldIcon()` هالة SVG خفيفة.

### ميزانية الأداء (تتبّع اليد يتقاسم معالج الرسوم)
| البند | الطبقة A | الطبقة B |
|---|---|---|
| الإطارات | ≤ ٣٠/ث | ≤ ٣٠/ث |
| دقة البكسل | ≤ 1.5 | 1 |
| المثلثات في المشهد | ≤ ١٠٠ ألف | ≤ ٥٠ ألفًا |
| الجسيمات | ≤ ٣٠ ألفًا (GPU) | ≤ ٢٠٠٠ (InstancedMesh) |
| Splat | واحد، ≤ ١٥٠ ألف splat | لا |
| المعالجة اللاحقة | تمريرة واحدة خفيفة | لا |

- لا ظلال حيّة على الهاتف. ظل ناعم تحت المجسّم = قرص شفاف بنسيج متدرّج.
- لا SSAO ولا bloom قوي (انظر ٤.٤).
- جرّب على الهاتف الأفقي مع تشغيل الكاميرا والتتبّع، فهو الأضعف، ويسخن بعد دقائق.

## ٤. تقنيات النخبة

### ٤.١ المواد بـ TSL وأسلوب «واضح على جهاز العرض»
- كل مادة مخصّصة تُكتب بـ **TSL** و`NodeMaterial` (مثل `MeshStandardNodeMaterial`). **لا `ShaderMaterial` ولا GLSL خام** مع `WebGPURenderer`. TSL يُترجَم إلى WGSL أو GLSL تلقائيًا.
- جهاز العرض في صف مضاء يمسح التفاصيل الدقيقة والظلال الخافتة. لذلك الأسلوب الأوضح:
  - **تظليل كرتوني** (`MeshToonNodeMaterial`) بدرجات لون قليلة مشبعة.
  - **حدود داكنة سميكة** لكل مجسّم: طريقة «الهيكل المقلوب» (نسخة مكبّرة قليلًا بـ `side: BackSide` ولون داكن). رخيصة وتعمل في كل الطبقات.
  - **ضوء حافة** (rim/fresnel) بـ TSL يفصل المجسّم عن الخلفية الفاتحة.
- الواقعية التصويرية مكانها اللحظة المدهشة فقط (Splat)، لا عناصر اللعب.

### ٤.٢ جسيمات معالج الرسوم (Compute)
- في الطبقة A تُحسب مواضع الجسيمات على المعالج الرسومي بـ `instancedArray` و`Fn(...).compute(count)` و`renderer.compute()`، وتُرسم بـ `SpriteNodeMaterial`.
- **طابق الكود** مع مثال `webgpu_compute_particles` في نسخة المستودع قبل الكتابة.
- الاستعمالات المناسبة: تجمّع الجسيمات في شكل المفهوم، وانفجار بلون الفئة عند الصواب، وتحوّل حالات المادة، ومطر قصاصات الختام.
- في الطبقة B: النسخة نفسها بـ InstancedMesh وتحديث على المعالج المركزي بعدد ≤ ٢٠٠٠.

### ٤.٣ Gaussian Splatting: الشيء الحقيقي في اللعبة
- **ما هو:** تمثيل مصوّر من الواقع بآلاف «البقع» الملوّنة، يعطي واقعية تصويرية بلا نمذجة.
- **المحرّك:** three.js أضاف عارض Splat أصليًا في **r186** (نوع `GaussianSplat` مع محمّلات SPZ وPLY وKSPLAT وglTF)، ويحتاج **WebGPURenderer** فهو للطبقة A فقط. طابق الكود مع مثال `webgpu_gaussian_splat`.
- البديل الخارجي: مكتبة **Spark** (MIT) تعمل على WebGL2 مع `WebGLRenderer`؛ لا تخلطها مع `three/webgpu` في الصفحة نفسها.
- **خط الإنتاج:**
  1. صوّر الشيء الحقيقي (محارة، صخرة، نبتة، قطعة تراثية) بتطبيق مثل **Scaniverse** أو **Polycam** على الآيباد.
  2. نظّفه واقصصه في **SuperSplat** (في المتصفح).
  3. صدّره **SPZ** (أصغر صيغة)، ≤ ١٥٠ ألف splat و≤ ٣ م.ب.
- **القواعد:**
  - مجسّم Splat **واحد** في اللعبة، يُحمَّل بكسل بعد بدء اللعبة، ويُعرض في الافتتاح أو لحظة الكشف أو الختام.
  - **ليس هدفًا لليد**: الأهداف تبقى مجسّمات أو بطاقات عادية.
  - **الخصوصية:** لا تصوّر طلابًا ولا وجوهًا ولا مكانًا يُعرف منه الطلاب.
  - في الطبقتين B وC يظهر بديله: مجسّم GLB أو صورة.
  - الألوان الواقعية تبهت على جهاز العرض؛ ضعه على خلفية بلون متباين وأضف هالة خلفه.

### ٤.٤ المعالجة اللاحقة (خفيفة جدًا)
- بنظام `PostProcessing` مع عقد TSL، **لا** `EffectComposer` القديم.
- المسموح في الطبقة A تمريرة واحدة: توهج انتقائي صغير على عنصر الصواب، أو تدرّج لوني سينمائي في الافتتاح والختام.
- الـ bloom على خلفية فاتحة يبهت الصورة كلها؛ استعمل بدله هالة مرسومة (قرص شفاف) أو ضوء حافة.

### ٤.٥ انتقالات الشاشات
- **View Transitions API** (`document.startViewTransition`) للانتقال بين القائمة واللعب والنتيجة: انزلاق أو تكبير ناعم بسطر CSS، مدعوم في Safari الحديث وكروم.
- افحص الدعم أولًا، ودونه انتقال فوري. تعطيلها مع تقليل الحركة.

### ٤.٦ شخصيات متحركة ثنائية الأبعاد (اختياري)
- لرسوم متحركة تفاعلية خفيفة (شخصية ترشد الطلاب) يمكن استعمال **Rive** (المشغّل برخصة MIT) بشرط استضافة ملفاته وملف wasm محليًا، وألا يزيد الحجم عن ٣٠٠ ك.ب. وإلا فـ SVG مع CSS.

- **الطريقة:**
  1. صورة مرجعية نظيفة: خلفية شفافة أو بيضاء، والشيء كاملًا، ومن زاوية ثلاثة أرباع.
  2. ولّد، ثم افحص الشكل علميًا (عدد الأرجل، الأجزاء، النسب). المولّد يخمّن الجوانب غير الظاهرة وقد يخطئ.
  3. اضغط (القسم التالي).
- **الرخص:** تحقق من رخصة النموذج أو الخدمة لكل أصل. بعض النماذج برخص مجتمعية مقيّدة، وبعض الخطط المجانية تشترط CC-BY أو تمنع الاستعمال التجاري. والصورة المرجعية نفسها يجب أن تكون مرخّصة أو من عملك.
- سجّل في `ASSETS.md`: «مولَّد بـ <النموذج> من <الصورة ورخصتها>».

### الضغط (إلزامي لكل GLB)
- عبر **glTF-Transform** في جلسة Claude Code:
  ```bash
  npx @gltf-transform/cli optimize in.glb out.glb --compress meshopt --texture-compress ktx2 --texture-size 512
  ```
  - `ktx2` يحتاج أداة KTX-Software مثبتة؛ إن لم تتوفر فاستعمل `--texture-compress webp`.
- في اللعبة: `GLTFLoader` مع `setMeshoptDecoder(MeshoptDecoder)`، و`KTX2Loader` مع `setTranscoderPath('/board-kit/vendor/three/addons/libs/basis/')` و`detectSupport(renderer)` بعد `init()`.
- **الحدود:** النسيج ≤ ٥١٢ بكسل (١٠٢٤ للمجسّم الرئيسي فقط)، والنماذج كلها ≤ ٢ م.ب.
- **الحجم الكلي لأصول اللعبة:** ≤ ٣ م.ب للأساسي، + Splat واحد اختياري ≤ ٣ م.ب يُحمَّل بكسل للطبقة A فقط.

**قواعد السلامة والوضوح:**
- لا وميض بأكثر من ٣ مرات في الثانية (الصرع الحساس للضوء).
- لا يغطي أي مؤثر الأهداف أثناء اللعب.
- **تقليل الحركة:** احترم `prefers-reduced-motion` و`data-motion="reduce"`: الطبقة C، ومدد أقصر، وبلا حركة كاميرا.
- **التأخير:** الصورة على السبورة قد تتأخر ثانية في انعكاس الشاشة (الملف 01)، فلا تعتمد على توقيت يطلب من الطالب «الآن!».

## ٧. الصوت
- **مؤثرات مُركّبة بـ Web Audio** (بلا ملفات ولا حقوق). في المحرّك: `sfx.pick/correct/wrong/back/click/win`.
  - ركّب مثلها عند الحاجة: هبوب (ضجيج عبر مرشّح متحرّك)، ولمعان (نغمات عالية متتابعة)، وضربة منخفضة (موجة جيبية تهبط).
- **صوت مكاني للفريقين:** `StereoPannerNode` يضع أصوات الفريق الأيمن يمينًا والأيسر يسارًا، فيعرف كل فريق صوته. (أثره يظهر فقط إن كانت سمّاعة جهاز العرض ستيريو؛ لا تعتمد عليه وحده.)
- **موسيقى خلفية توليدية خافتة** (≈ ٥٪ من الصوت):
  - نغمة أرضية ولحن متجوّل على **مقام**: الحجاز `[0,1,4,5,7,8,10]`، أو البياتي، أو الرست، أو الخماسي.
  - مقام مختلف لكل لعبة، وإيقاع أسرع للتشويق بعد منتصف اللعبة.
  - تتوقف مع إيقاف المؤثرات في لوحة المعلّم.
- **نطق** الاسم بالعربية عند الصواب: `say()`.
- **ملفات صوت** (اختياري): CC0 فقط، mp3 أو ogg ≤ ١٠٠ ك.ب، في `assets/`، وتُشغّل بعد أول لمسة (شرط iOS).

## ٨. دقة التتبّع: تحسينات المحرّك (لا تُكتب داخل لعبة)
تتبّع اليد والمعايرة من مسؤولية `board-kit`، ولا تعيد لعبة كتابتها. إن طلب المعلّم دقة أعلى، **اقرأ كود المحرّك أولًا** لتعرف ما هو موجود، ثم اقترح ما ينقص كتغيير في `board-kit` يُنفَّذ عبر Claude Code ويُختبر في الصف:
- **تنعيم One Euro Filter** لمؤشر اليد: يزيل الارتعاش عند الثبات ولا يضيف تأخيرًا عند الحركة.
- **الاستدلال في Web Worker** أو بمفوّض GPU في MediaPipe (`delegate: 'GPU'`) حتى لا ينافس الرسم.
- **معايرة إسقاطية بأربع نقاط** (homography) لتصحيح ميل الكاميرا على السبورة.
- **التأكد قبل الاعتماد:** أي تغيير في المحرّك يُجرَّب على الآيباد والهاتف الأفقي في الصف قبل اعتماده لكل الألعاب.
